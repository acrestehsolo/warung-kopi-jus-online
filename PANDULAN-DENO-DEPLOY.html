1
Upload file ke GitHub

File-file ini sudah ada di zip. Upload ke repo GitHub kamu (acrestehsolo/warung-kopi-jus-online):

  • api/deno.ts — backend API
  • deno.json — config Deno Deploy
  • js/store.js — yang sudah diupdate (ada SERVER_URL)
  • README.md — panduan (optional)
Cara upload: GitHub → repo → Add file → Upload files → drag file-file di atas → Commit changes
✅ Setelah ini: file-file ada di GitHub, siap di-deploy ke Deno.
2
Buka console.deno.com & Sign In
Klik: buka browser → ketik https://console.deno.com → Sign in dengan GitHub kamu.

Kalau belum punya akun, bisa sign in dengan GitHub (gratis).

3
Create Organization
Klik: tombol Create Organization (atau "+ New Organization")
Isi: Nama organisasi — bisa pakai nama kamu, contoh: acrestehsolo atau warung-wahyu
⚠️ Catatan: Nama organisasi AKAN jadi bagian dari URL deploy kamu. Pilih nama yang simpel. Nama tidak bisa diganti setelah dibuat.
✅ Setelah ini: kamu masuk ke halaman organisasi. Akan ada tombol + New App.
4
Create App & Pilih Repo
Klik: tombol + New App

Kamu akan diminta pilih GitHub repository:

Pilih: acrestehsolo/warung-kopi-jus-online (repo kamu)
⚠️ Catatan: Jika repo tidak muncul, klik "Add another GitHub account" atau "Configure GitHub App permissions" untuk memberi akses ke repo kamu.
5
Edit Build Config

Ini bagian PENTING — configure backend API kamu:

Klik: tombol "Edit build config"

Isi form seperti ini:

FieldIsi Dengan
Framework presetNo Preset
Install commanddeno install
Build commandKosong (tidak perlu build)
Runtime configurationDynamic
Dynamic Entrypointapi/deno.ts
Regionglobal (US + Europe)
⚠️ Jangan salah: Entrypoint harus api/deno.ts (bukan main.ts atau server.js). Ini file yang jalan di Deno Deploy.
6
Create App & Deploy
Klik: tombol "Create App"

Deno Deploy akan mulai build. Tunggu beberapa detik sampai status jadi "Deployed".

URL Deploy kamu akan seperti ini:
https://warung-kopi-jus-online.{nama-organisasimu}.deno.dev
Salin URL ini — nanti dipakai di Step 9.
⚠️ Masih belum selesai! KV database belum di-assign. Tanpa KV, order tidak bisa disimpan. Lanjut ke Step 7.
7
Provision KV Database

KV adalah penyimpanan order. Di platform baru, ini harus di-provision terpisah.

Klik: menu "Databases" di navigation bar (kiri)
Klik: tombol "Provision Database"
Isi:
  • Database engine: Deno KV
  • Name: warung-orders (atau nama bebas)
Klik: Save / Provision
✅ KV database dibuat. Sekarang assign ke app kamu.
8
Assign KV ke App

Beri tahu Deno Deploy: "App ini pakai KV database ini".

Klik: tombol "Assign" di samping KV database yang baru dibuat
Pilih: app kamu (warung-kopi-jus-online) dari dropdown
Klik: Assign / Confirm
✅ Status berubah jadi "Connected" — app kamu sekarang terhubung ke KV. Order bisa disimpan!
9
Pasang URL ke store.js

Beritahu aplikasi web kamu URL backend Deno Deploy. Edit file js/store.js di GitHub:

Cara: GitHub → repo → klik js/store.js → klik icon pensil (edit)

Cari baris ini (dekat awal file):

// >>> GANTI DENGAN URL BACKEND Deno Deploy <<
const SERVER_URL = "YOUR-DENO-URL";

Ganti menjadi (ganti dengan URL kamu dari Step 6):

const SERVER_URL = "https://warung-kopi-jus-online.{nama-organisasi}.deno.dev";
⚠️ Tempel URL dengan benar — tanpa tanda kutip tambahan. Tepat seperti yang muncul di Step 6.
Klik: Commit changes → Push ke main branch
✅ store.js diupdate. Deno Deploy otomatis redeploy (karena connected ke GitHub).

Pertanyaan Sering (FAQ)

Q: Kalau admin offline (tidak ada internet)?

Admin tidak bisa menerima order baru. Order yang sudah masuk sebelum offline tetap bisa dilihat. Order butuh internet untuk berjalan: customer → Deno Deploy → admin.

Q: Apa bedanya Deno Deploy dengan GitHub Pages?

GitHub PagesDeno Deploy
JinisStatik (HTML/CSS/JS)Dinamis (backend jalan)
Server jalan?❌✅
Bisa terima order?❌ (hanya localStorage)✅ (ke KV cloud)
Admin bisa lihat order?❌ (browser berbeda)✅ (dari cloud)

Q: Biaya?

Gratis. 1 juta request/bulan, 1 GB KV storage. Cukup untuk warung kecil.

Q: Laptop harus menyala?

Tidak. Server jalan di cloud Deno. Laptop bisa mati. Order tetap masuk.

Q: Kalau mau ganti URL Deno Deploy?

Edit SERVER_URL di js/store.js → push ke GitHub. Selesai.
